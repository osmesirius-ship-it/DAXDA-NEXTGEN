# DAXDA Community Operations Network
## Safeguarding-First Pilot Protocol

### Objective
Test whether a structured, human-governed operational layer improves:
- site readiness
- accountability for open tasks
- food/allergy procedure compliance
- staffing / adult coverage documentation
- facility and equipment readiness
- reduced administrative rework

### Non-negotiable design principle
The system is **not** a classifier or decision-maker for children, families, or individual program participants. It records operational control state only.

### Permitted data
- site serial number
- site type
- site lead role
- operational task title and status
- training/certification process status (no personal documents in the prototype)
- inventory state
- facility readiness state
- aggregate program capacity

### Prohibited data
- names of minors or families
- child behavioral records
- medical or disability information
- alleged incident narratives
- abuse, trauma, legal, immigration, school, or child welfare records
- precise addresses, dates of birth, photographs, or identifying combinations

### Escalation rule
DAXDA may flag: "a required operational safeguard has not been verified."
A named qualified adult must decide:
- whether the gap is real
- what action is required
- whether legal, emergency, or mandatory-reporting duties apply

### Pilot metrics
1. Percentage of readiness checks completed before opening.
2. Time from action creation to human completion.
3. Number of missed operational controls per site per week.
4. Number of repeat errors / rework events.
5. Staff-reported clarity and workflow burden.
6. Number of escalations routed to a named human lead.
